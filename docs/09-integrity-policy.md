# 去伪存真：内容完整性守则

> “精神洁癖”不是口号，而是几条宁可少做、也不装懂的硬规则。

## 1. 五条铁律

1. **无出处，不发布**
   - 每一条结构化解读必须带 `ref`（章节、页码或原文片段）。
   - 无法在原文中定位的判断，不进入发布内容。
2. **无许可，不演绎**
   - CC BY-NC 不做商业使用；CC BY-ND 不做全文翻译/改编。
   - 未知许可证 fail-closed：只展示元数据。
3. **未复核，不宣称**
   - AI 辅助整理的解读统一标注「待复核」。
   - 只有写入 `review_log` 且状态为 `reviewed` 的内容才显示「已复核」。
4. **有争议，要并列**
   - 标注【学界存在争议】，并列多方证据与复现结果。
   - 平台不做学术仲裁，不给“真/假”的最终判决。
5. **撤稿或更正，立即下架并标注**
   - 当前为人工流程；接入撤稿数据库后应自动触发复核与下架。
   - 不能因为“内容已经写了”而保留错误结论。

## 2. 原型里的诚实边界

| 事项 | 当前状态 | 对外表述 |
| --- | --- | --- |
| 许可证 | 规则已编码，逐篇来源部分已录入 | “已标注来源” / “待核对” |
| 结构化解读 | 平台整理，未接生产级模型 | “AI 辅助整理 · 待复核” |
| 段落溯源 | 章节级示意，尚不可跳转原文 | “章节级示意” |
| 撤稿/更正 | 未接入数据库 | “未接入，不能视为已核验” |
| 同行评审 | 仅区分预印本/期刊 | 不声称“已验证论文质量” |
| 引用量 | 来自数据集，可能过期 | 标注为演示数据 |

**原则**：宁可显示灰色“未接入”，也不给一个绿色的“已核验”。

## 3. 质量闸门

```bash
node tools/quality-check/check.mjs
node --test tools/quality-check/check.test.mjs
```

检查器在以下情况直接失败（退出码 1）：

- 缺少标题、作者、期刊、年份、摘要、许可证或链接。
- 论文 id 重复。
- 出现未收录的许可证。
- `UNVERIFIED` 文献包含结构化解读，或标记为可深度处理。
- 解读段落缺少正文或 `ref`；段落少于 3 段。
- 概念卡或专题引用了不存在的论文。

提醒项（不阻断）：

- 解读少于 5 段。
- 摘要过短。
- 链接不是完整 URL。

## 4. 详情页的完整性面板

每篇论文展示：

- **来源类型**：预印本 / 期刊会议。
- **许可证**：已标注来源 / 待核对。
- **结构化解读**：已复核 / AI 辅助整理·待复核 / 无。
- **段落溯源**：章节级示意 / 不适用。
- **撤稿更正**：未接入。

同时提供“报告错误 / 质疑”入口：自动把焦点移到讨论区并预填【质疑】，要求用户说明质疑依据。

## 5. 编辑复核清单

发布前逐项确认：

- [ ] 标题、作者、年份、期刊与 DOI/arXiv 一致。
- [ ] 许可证来源已记录（URL 或数据库字段）。
- [ ] 每条解读都有原文出处，且不是逐句翻译。
- [ ] 研究局限与争议没有被省略。
- [ ] 数值、单位、图表引用没有跨段拼接。
- [ ] AI 生成/辅助内容已标识。
- [ ] 撤稿、更正、学术不端风险已检查（或明确标注未接入）。

## 6. 纠错与撤稿流程

1. 用户在讨论区或“报告错误”入口提出质疑。
2. 编辑在复核工作台查看内容与许可证来源。
3. 需要修改的解读退回 `pending`，更新后重新复核。
4. 撤稿/更正文献：下架深度内容，保留元数据与风险提示。
5. 全流程写入 `review_log`；对外保留变更说明。

## 7. 反“虚荣指标”

- 不以停留时长、点击率作为唯一目标。
- 北极星是「读完 + 展开证据 + 一次互动」，不是“刷到了”。
- 不为了留存而推荐争议内容；争议标签用于教育，不用于流量。
- 不把 AI 生成量当作内容规模；复核过的内容才算内容。

## 8. 与许可证策略的关系

完整性检查是编辑规则；许可证校验是法律/合规规则。两者都必须通过：

- 许可证校验器：`tools/license-check/check.mjs`
- 完整性检查器：`tools/quality-check/check.mjs`
- 入库流水线：`server/ingest.mjs`（拒绝能力不写入可展示字段）

> 去伪存真的最低标准：**说出来的每一句，都能指出它从哪里来；指不出来的，就不说。**
