# 5 人可用性测试方案

> 目标：验证“溯源—解读—讨论”闭环是否可理解、可用、可测量。总时长约 60 分钟（5 人 × 25 分钟 + 分析）。

## 1. 测试目标与假设

**核心假设**

1. 用户能在 2 分钟内找到一篇论文，并说出它“怎么证明”而不只是“发现了什么”。
2. 用户能理解「证据段落」与「许可证能力」的含义，不把它们当成装饰。
3. 用户愿意围绕单篇论文留下问题或收藏，而不只是刷过。

**观察指标**

- 任务完成率（5 个任务）。
- 读到达标率：事件层面的「读完 + 展开证据 + 一次互动」比例。
- 卡点与误读：用户在哪里皱眉、犹豫、点错。
- SUS-lite：5 个 1–5 分问题，总分 25。

## 2. 参与者（5 人）

| 编号 | 画像 | 招募来源 |
| --- | --- | --- |
| P1 | 本科生，刚开始读文献 | 学院群 / 课程群 |
| P2 | 低年级研究生，非 AI 方向 | 实验室 / 同学 |
| P3 | 科技爱好者，平时刷科普短视频 | 社团 / 朋友 |
| P4 | 高中理科教师或科普作者 | 教师群 / 科普社群 |
| P5 | 普通用户，无科研背景 | 家人 / 非技术朋友 |

排除：本项目参与者、已熟悉原型的人。

## 3. 测试前准备

```bash
node server/ingest.mjs              # 重置内容、事件与复核状态
PORT=8123 node server/server.mjs
```

- 使用无痕窗口；每个参与者独立会话。
- 不需要设置 `XLW_REVIEW_TOKEN`（除非专门测试令牌流程）。
- 准备计时器、录屏/录音（征得同意）与记录表。
- 打开 **http://localhost:8123**。

## 4. 开场（3 分钟）

> “我们在测试一个科学论文科普产品，想看看普通人能不能读懂论文的论证过程。没有标准答案，也不会评价你；请边操作边说出你的想法。可以随时停止。”

记录：编号、画像、时间、设备。

## 5. 任务脚本（约 17 分钟）

### 任务 A：找到一篇经典论文并说出证据（4 分钟）

> “请找到爱因斯坦 1905 年关于光电效应的论文，读一下它的结论。然后告诉我：作者用什么实验支持这个结论？”

观察点：

- 是否使用专题、搜索或知识库入口。
- 是否打开详情并阅读摘要/解读。
- 是否点击 `§` 出处标签（`evidence_expand` 事件）。
- 是否混淆“结论”和“实验设计”。

成功标准：打开详情 + 指出至少一个实验设计要素（频率、截止电压、对照等）。

### 任务 B：理解一篇 AI 论文的局限（4 分钟）

> “在 AI 必读 Top50 里找到 ResNet，告诉我这篇论文承认了哪些局限。”

观察点：

- 是否能从 50 篇中找到目标（搜索/专题排序）。
- 是否读到“研究局限”段。
- 是否注意到「AI 辅助整理 · 待复核」标识，并理解其含义。

成功标准：找到 ResNet + 说出至少一条局限 + 注意到待复核标识。

### 任务 C：判断一篇论文能否翻译（3 分钟）

> “打开 LK-99 这篇论文，看看平台能不能提供全文翻译，为什么？”

观察点：

- 是否找到「许可证能力」面板。
- 是否能解释“arXiv 许可 / 禁止演绎”的含义。
- 是否误以为“能看摘要”等于“能翻译全文”。

成功标准：正确指出全文翻译被拒绝，并给出许可证或“待核对”原因。

### 任务 D：收藏与提问（3 分钟）

> “假设你想跟进这篇论文，请收藏它，并在讨论区留一个关于实验或结论的问题。”

观察点：

- 收藏入口是否可发现。
- 评论表单的规则提示是否被读到。
- 是否愿意留下真实问题（而非“test”）。

成功标准：完成收藏 + 提交一条与论文相关的问题。

### 任务 E：编辑视角（3 分钟）

> “假设你是平台编辑，请找到所有许可证待核对的内容，并导出一份清单。”

观察点：

- 是否发现「复核」入口。
- 是否会用筛选与导出。
- 是否理解复核状态与许可证来源。

成功标准：筛选出 UNVERIFIED + 导出 CSV。

## 6. 复盘问题（5 分钟）

1. 哪个页面最让你困惑？为什么？
2. “证据段落”和“许可证能力”你会怎么向朋友解释？
3. 你会为了读懂一篇论文专门打开这个产品吗？在什么场景下？
4. 你更想要：更短的解读、更多可视化、还是更多原文细节？
5. SUS-lite（1–5 分）：
   - 我很快找到了想看的论文。
   - 我理解了论文的论证过程。
   - 我相信这些解读有原文依据。
   - 我愿意再次使用。
   - 我愿意参与讨论或收藏。

## 8. 判定规则

- **继续方向**：≥4/5 完成 A、B、C；≥3/5 完成 D；≥3/5 认为“能理解论证过程”。
- **需要改信息架构**：≥2 人找不到专题/搜索/证据标签。
- **需要改内容形态**：≥3 人只读摘要、不展开证据；或普遍觉得解读太长。
- **暂停扩展功能**：如果读到达标率 < 20%，优先改内容与引导，不加新模块。

## 9. 收尾与重置

- 询问是否愿意留下联系方式参加后续测试。
- 测试结束后运行 `node server/ingest.mjs` 清空事件与复核状态。
- 汇总 5 份记录，输出一页结论：最严重的 3 个问题、最值得保留的 3 个设计、下一步是否进入 M2。
